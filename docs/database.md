# Database Design

## Overview

- **Database:** PostgreSQL, chosen for relational modeling, primary and foreign keys, integrity constraints, indexing, and reliable transactions.
- **Access:** the backend uses the `pg` library with hand-written SQL (no ORM).
- **Migrations:** schema changes are managed with `node-pg-migrate`.

## Entity Hierarchy

```
websites (1) ──< visitors (many) ──< sessions (many) ──< events (many)
```

- A website has many visitors.
- A visitor has many sessions.
- A session has many events.

The SDK generates `visitor_id`, `session_id`, and `event_id`, so they are only unique within a website. Every child table therefore carries `website_id` and identifies its rows (and its parent) by a composite key that starts with it.

## Migration History

1. Create `websites` table.
2. Add unique constraint on `domain`.
3. Rename the constraint to `domain_unique_constraint`.
4. Create `visitors` table.
5. Create `sessions` table.
6. Create `events` table.
7. Remove the surrogate `id` columns from `visitors`, `sessions`, and `events`, and replace them with composite primary keys.

## Table: `websites`

Registered website properties.

| Column                 | Type         | Constraints                                   | Description                                                                                            |
| ---------------------- | ------------ | --------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `id`                   | UUID         | Primary key, default `uuidv7()`               | The Website ID the SDK uses to identify which property is sending data.                                |
| `name`                 | VARCHAR(100) | Not null                                      | Display name chosen by the owner.                                                                      |
| `domain`               | VARCHAR(255) | Not null, unique (`domain_unique_constraint`) | Domain of the registered website.                                                                      |
| `timezone`             | VARCHAR(100) | Not null, default `UTC`                       | The website's preferred timezone.                                                                      |
| `dashboard_token_hash` | TEXT         | Not null                                      | Hash of the dashboard access token. The original token is returned to the owner once, at registration. |
| `recovery_key_hash`    | TEXT         | Not null                                      | Hash of the recovery key. The original key is returned to the owner once, at registration.             |
| `created_at`           | TIMESTAMPTZ  | Default `current_timestamp`                   | When the website was registered.                                                                       |
| `updated_at`           | TIMESTAMPTZ  | Default `current_timestamp`                   | When the website was last modified.                                                                    |

---

## Table: `visitors`

Unique anonymous visitors, scoped to a website.

**Primary key:** `(website_id, visitor_id)`

| Column          | Type        | Constraints                                   | Description                                         |
| --------------- | ----------- | --------------------------------------------- | --------------------------------------------------- |
| `website_id`    | UUID        | Not null, FK → `websites.id` (cascade delete) | The website the visitor belongs to.                 |
| `visitor_id`    | UUID        | Not null                                      | Anonymous visitor identifier, generated by the SDK. |
| `first_seen_at` | TIMESTAMPTZ | Not null, default `now()`                     | When the visitor was first observed.                |
| `last_seen_at`  | TIMESTAMPTZ | Not null, default `now()`                     | The visitor's most recent activity.                 |

---

## Table: `sessions`

Individual browsing sessions. A session expires after 30 minutes of inactivity.

**Primary key:** `(website_id, session_id)`
**Foreign key:** `(website_id, visitor_id)` → `visitors(website_id, visitor_id)` (cascade delete)

| Column             | Type        | Constraints                                   | Description                                             |
| ------------------ | ----------- | --------------------------------------------- | ------------------------------------------------------- |
| `website_id`       | UUID        | Not null, FK → `websites.id` (cascade delete) | The website the session belongs to.                     |
| `session_id`       | UUID        | Not null                                      | Session identifier, generated by the SDK.               |
| `visitor_id`       | UUID        | Not null                                      | The visitor who owns the session, generated by the SDK. |
| `started_at`       | TIMESTAMPTZ | Not null, default `now()`                     | When the session started.                               |
| `last_activity_at` | TIMESTAMPTZ | Not null, default `now()`                     | Most recent activity in the session.                    |

---

## Table: `events`

Tracked website activity, including page views and custom events.

**Primary key:** `(website_id, event_id)`
**Foreign key:** `(website_id, session_id)` → `sessions(website_id, session_id)` (cascade delete)

| Column        | Type         | Constraints               | Description                                                                                                    |
| ------------- | ------------ | ------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `website_id`  | UUID         | Not null                  | The website the event belongs to. Part of the session foreign key, so it always matches the session's website. |
| `session_id`  | UUID         | Not null                  | The session in which the event occurred.                                                                       |
| `event_id`    | UUID         | Not null                  | Unique event identifier, generated by the SDK. Used for idempotency.                                           |
| `event_name`  | VARCHAR(255) | Not null                  | Type of event, e.g. `page_view`, `button_click`, `purchase`.                                                   |
| `properties`  | JSONB        | Not null, default `{}`    | Event-specific data. Lets custom events carry different properties without new columns.                        |
| `url`         | TEXT         | Not null                  | URL of the page where the event occurred.                                                                      |
| `title`       | TEXT         |                           | Title of that page.                                                                                            |
| `referrer`    | TEXT         |                           | Referring URL, when available.                                                                                 |
| `occurred_at` | TIMESTAMPTZ  | Not null                  | When the event happened on the website.                                                                        |
| `received_at` | TIMESTAMPTZ  | Not null, default `now()` | When the backend received the event. Kept separate from `occurred_at` to account for delay between the two.    |

## Design Decisions

- Every website has its own Website ID, and all child data is tied to it through `website_id`.
- SDK-generated IDs are only unique per website, so identity is always the composite `(website_id, <id>)`.
- Composite foreign keys guarantee that a session's website matches its visitor's, and an event's website matches its session's.
- Deleting a website cascades to its visitors, sessions, and events.
- Event primary keys prevent duplicate events, which makes ingestion idempotent.
- Credentials are stored only as hashes.
- Visitors and sessions are stored separately from events, and the backend must create them before inserting an event.
