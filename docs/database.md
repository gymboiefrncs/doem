# Database Design

## Database Technology

The project uses PostgreSQL as its primary relational database.

PostgreSQL was selected because it provides:

- Relational data modeling.
- Primary keys and foreign keys.
- Constraints for data integrity.
- Indexing for efficient queries.
- Reliable transaction support.

The backend communicates with PostgreSQL using the `pg` library.

SQL is currently written directly rather than using an ORM.

## Database Migrations

Database schema changes are managed using `node-pg-migrate`.

## Current Database Scope

The current schema contains four tables:

1. `websites`
2. `visitors`
3. `sessions`
4. `events`

Applied migration sequence:

1. Create `websites` table.
2. Add unique constraint on `domain`.
3. Rename the constraint to `domain_unique_constraint`.
4. Create `visitors` table.
5. Create `sessions` table.
6. Create `events` table.

## Table: `websites`

Stores registered website properties.

- `id` UUID primary key.
- `name` VARCHAR(100) not null.
- `domain` VARCHAR(255) not null, unique.
- `timezone` VARCHAR(100) not null, default `UTC`.
- `dashboard_token_hash` TEXT not null.
- `recovery_key_hash` TEXT not null.
- `created_at` TIMESTAMPTZ.
- `updated_at` TIMESTAMPTZ.

### Column Details

**`id`**

A UUID generated by PostgreSQL using `uuidv7()`.

It serves as the Website ID used by the SDK to identify which website property is sending analytics data.

**`name`**

The display name chosen by the website owner.

**`domain`**

The domain associated with the registered website.

**`timezone`**

The website's preferred timezone.

**`dashboard_token_hash`**

Stores the hash of the dashboard access token. The original token is generated returned to the website owner during registration.

**`recovery_key_hash`**

Stores the hash of the recovery key. The original key is returned to the website owner during registration

**`created_at`**

Records when the website property was registered.

**`updated_at`**

Records when the website property was last modified.

### Important Design Decisions

- Every website property has its own Website ID.
- Website domain is unique.
- Credentials are stored as hashes.

## Table: `visitors`

Stores unique anonymous visitors associated with a website.

- `id` BIGINT primary key.
- `website_id` UUID not null, references `websites.id`.
- `visitor_id` UUID not null.
- `first_seen_at` TIMESTAMPTZ not null.
- `last_seen_at` TIMESTAMPTZ not null.

### Column Details

**`id`**

An internally generated identifier for the visitor record.

**`website_id`**

References the website associated with the visitor.

**`visitor_id`**

A UUID identifying the anonymous visitor. This is generated by the sdk

**`first_seen_at`**

Records when the visitor was first observed.

**`last_seen_at`**

Records the visitor's most recent activity.

### Important Design Decisions

- Visitor identities are scoped to individual websites.
- The combination of `website_id` and `visitor_id` is unique.
- A visitor can have multiple sessions.

## Table: `sessions`

Stores individual browsing sessions belonging to visitors.

- `id` BIGINT primary key.
- `website_id` UUID not null, references `websites.id`.
- `visitor_id` UUID not null.
- `session_id` UUID not null.
- `started_at` TIMESTAMPTZ not null.
- `last_activity_at` TIMESTAMPTZ not null.

### Column Details

**`id`**

An internally generated identifier for the session record.

**`website_id`**

References the website associated with the session.

**`visitor_id`**

Identifies the visitor associated with the session. This is generated by the sdk

**`session_id`**

A UUID identifying an individual browsing session. This is generated by the sdk

**`started_at`**

Records when the session started.

**`last_activity_at`**

Records the most recent activity within the session.

### Important Design Decisions

- A session belongs to one visitor.
- A visitor can have multiple sessions.
- Session identities are scoped to individual websites.
- A session expires after 30 minutes of inactivity.

## Table: `events`

Stores tracked website activities, including page views and custom events.

- `id` BIGINT primary key.
- `website_id` UUID not null, references `websites.id`.
- `session_id` UUID not null.
- `event_id` UUID not null.
- `event_name` VARCHAR(255) not null.
- `properties` JSONB not null.
- `url` TEXT not null.
- `title` TEXT.
- `referrer` TEXT.
- `occurred_at` TIMESTAMPTZ not null.
- `received_at` TIMESTAMPTZ not null.

### Column Details

**`id`**

An internally generated identifier for the event record.

**`website_id`**

Identifies the website associated with the event.

**`session_id`**

Identifies the session during which the event occurred.

**`event_id`**

A UUID uniquely identifying an individual event. This is generated by the sdk.
For idempotency

**`event_name`**

Identifies the type of event being recorded.

Examples include `page_view`, `button_click`, and `purchase`.

**`properties`**

A JSONB column containing additional event-specific information.

This allows custom events to store different properties without requiring additional database columns.

**`url`**

Stores the URL of the page where the event occurred.

**`title`**

Stores the title of the page where the event occurred.

**`referrer`**

Stores the referring URL, when available.

**`occurred_at`**

Records when the event occurred on the website.

**`received_at`**

Records when the backend received the event.

### Important Design Decisions

- Events are associated with a website and session.
- Event IDs are unique within a website.
- JSONB allows flexible storage of custom event properties.
- `occurred_at` and `received_at` are separate to account for differences between event occurrence and server receipt times.

---

## Important Design Decisions

- Every website has its own Website ID.
- Visitor and session records are stored separately from events.
- A visitor can have multiple sessions.
- A session can contain multiple events.
- Website ownership is maintained through `website_id`.
- Unique constraints prevent duplicate records.
- Foreign keys maintain referential integrity.
