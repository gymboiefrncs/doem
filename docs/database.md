# Database Design

## Database Technology

The project uses PostgreSQL as its primary relational database.

PostgreSQL was selected because it provides:

- Relational data modeling.
- Primary keys and foreign keys.
- Constraints for data integrity.
- Indexing for efficient queries.
- Reliable transaction support.

The backend communicates with PostgreSQL using the `pg` library.

SQL is currently written directly rather than using an ORM.

## Database Migrations

Database schema changes are managed using `node-pg-migrate`.

## Current Database Scope

The current schema contains one table: `websites`.

Applied migration sequence:

1. Create `websites` table.
2. Add unique constraint on `domain`.
3. Rename the constraint to `domain_unique_constraint`.

## Table: `websites`

Stores registered website properties.

- `id` UUID primary key.
- `name` VARCHAR(100) not null.
- `domain` VARCHAR(255) not null, unique.
- `timezone` VARCHAR(100) not null, default `UTC`.
- `dashboard_token_hash` TEXT not null.
- `recovery_key_hash` TEXT not null.
- `created_at` TIMESTAMPTZ.
- `updated_at` TIMESTAMPTZ.

### Column Details

**`id`**

A UUID generated by PostgreSQL using `uuidv7()`.

It serves as the Website ID used by the SDK to identify which website property is sending analytics data.

**`name`**

The display name chosen by the website owner.

**`domain`**

The domain associated with the registered website.

**`timezone`**

The website's preferred timezone.

**`dashboard_token_hash`**

Stores the hash of the dashboard access token.

The original token is generated securely and returned to the website owner during registration. It is not stored in plaintext.

**`recovery_key_hash`**

Stores the hash of the recovery key.

The recovery key is separate from the dashboard token.

**`created_at`**

Records when the website property was registered.

**`updated_at`**

Records when the website property was last modified.

## Important Design Decisions

- Every website property has its own Website ID.
- Website domain is unique.
- Credentials are stored as hashes, not plaintext.
